# 開発部｜課題と目標（2027年度）

## 役割
アプリ・決済の仕組みを作り、止めずに動かす。

## 2026年度の振り返り
- エンジニア 32名。新機能より障害対応・古い仕組みの手直しに時間の45%を取られた
- 決済まわりの障害が年6回（うち2回は半日以上、応援金の入金遅れ）
- 各部からの開発依頼が 40件たまっている

## 課題
- 決済の仕組みが古く、新しい支払い方法を足しにくい・止まりやすい
- 人手不足で、各部の依頼に応えられていない

## 2027年度の目標
- 決済基盤の刷新（障害ゼロ、PayPay・コンビニ払いに対応）
- ギフト機能のリリース（上期）
- CSのチャットボット連携
- 障害対応・手直しの時間を 45% → 25%

## 予算要望：5.2億円（前年 4.1億円）
| 項目 | 金額 |
|---|---|
| 既存エンジニア32名の人件費 | 3.2億円 |
| エンジニア +8名の人件費 | 0.8億円 |
| 決済基盤の刷新（外部委託含む） | 0.7億円 |
| サーバー・開発ツール費 | 0.5億円 |

## 優先順位（開発部の考え）
1. 決済基盤の刷新（止まると全売上に響く。支払い方法の追加もこれが前提）
2. ギフト機能
3. チャットボット連携（2人月なので小さい）

## 譲れない点・削れる点
- 譲れない：決済基盤の刷新
- 削れる：増員を 8名 → 5名にすると ▲0.3億円。ただしギフト機能は下期にずれる
